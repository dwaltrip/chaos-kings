## Relevant Architecture Decisions

These decisions from the planning doc guide this implementation:

### 1. Room Manager → Pure Data Structure
- RoomManager tracks membership only (no WebSocket knowledge)
- Server owns client connections separately
- Preserves v1's multi-connection semantics (multiple tabs per user)
- Uses inverse index for efficient cleanup on disconnect

### 2. Authentication → Keep Fastify Auth
- Continue using `req.currentUser` from Fastify auth middleware
- Extract userId on connection, pass to handler context

### 3. Message Format → Flat Envelope
- Use `{ type: 'domain:message-type', payload: {...} }` format
- Parse domain from namespaced type (no separate domain field)

### 4. Dependencies → Module Singleton
- wsBridge is module-level singleton with lazy initialization
- Domain code imports directly: `import { wsBridge } from '@/ws/server-bridge'`

### 5. Handler Context → Data-Only **[TENTATIVE]**
- Recommended: Keep context simple - `{ userId, connectionId }`
- Operations stay in ws-effects/bridge layer
- Actual shape lives in `apps/backend/src/ws-handler-context.ts` so the `ws/` package stays generic
- **Validate during implementation** - may need adjustment

### Step 1: Create Core Types

**File:** `apps/backend/src/ws/types.ts`

```ts
import type { ClientMessage, ServerMessage } from '@protocol/...';

// Connection identifier (generated by server via UUID)
export type ConnectionId = string;

// Handler signature
export type DomainHandler<
  TMessage extends { type: string },
  TContext
> = (
  payload: TMessage['payload'],
  context: TContext
) => void | Promise<void>;

// Handler map with context
export type HandlerMapWithCtx<TMessage extends { type: string }, TContext> = {
  [K in TMessage['type']]: DomainHandler<Extract<TMessage, { type: K }>, TContext>;
};

// Broadcast options for multi-tab support
export type BroadcastOptions = {
  excludeConnectionId?: ConnectionId;
};

// WS Bridge interface (what domain ws-effects use)
export interface WsBridge {
  broadcast(message: ServerMessage, opts?: BroadcastOptions): void;
  broadcastToRoom(roomId: string, message: ServerMessage, opts?: BroadcastOptions): void;
  sendToUser(userKey: string, message: ServerMessage): void;
  rooms: {
    join(roomId: string, connectionId: ConnectionId): void;
    leave(roomId: string, connectionId: ConnectionId): void;
    getMembers(roomId: string): Set<ConnectionId>;
  };
}
```

**Key points:**
- `ConnectionId` is infrastructure-level, not exposed to domain/kernel
- `DomainHandler`/`HandlerMapWithCtx` are fully generic; no app types live in `ws/`
- `BroadcastOptions.excludeConnectionId` supports multi-tab scenarios
- `WsBridge.sendToUser` works with an app-defined `userKey` (e.g., userId string)

### Step 2: Implement Room Manager

**File:** `apps/backend/src/ws/room-manager.ts`

**Goal:** Extract and adapt v1's room management logic, preserving multi-connection support.

**Reference:** Look at `backend/src/websocket/manager.ts` (v1) for the room bookkeeping logic.

**Key design:**
```ts
import type { ConnectionId } from './types';
import type { RoomId } from '@kernel/types';

export class RoomManager {
  // Which connections are in which rooms
  private rooms = new Map<RoomId, Set<ConnectionId>>();

  // Inverse index: which rooms each connection is in (for cleanup)
  private roomsForConnection = new Map<ConnectionId, Set<RoomId>>();

  join(connectionId: ConnectionId, roomId: RoomId): void {
    // Add to room
    if (!this.rooms.has(roomId)) {
      this.rooms.set(roomId, new Set());
    }
    this.rooms.get(roomId)!.add(connectionId);

    // Update inverse index
    if (!this.roomsForConnection.has(connectionId)) {
      this.roomsForConnection.set(connectionId, new Set());
    }
    this.roomsForConnection.get(connectionId)!.add(roomId);
  }

  leave(connectionId: ConnectionId, roomId: RoomId): void {
    // Remove from room
    const room = this.rooms.get(roomId);
    if (room) {
      room.delete(connectionId);
      if (room.size === 0) {
        this.rooms.delete(roomId);
      }
    }

    // Update inverse index
    const userRooms = this.roomsForConnection.get(connectionId);
    if (userRooms) {
      userRooms.delete(roomId);
      if (userRooms.size === 0) {
        this.roomsForConnection.delete(connectionId);
      }
    }
  }

  getMembers(roomId: RoomId): Set<ConnectionId> {
    return this.rooms.get(roomId) || new Set();
  }

  getRoomsForConnection(connectionId: ConnectionId): Set<RoomId> {
    return this.roomsForConnection.get(connectionId) || new Set();
  }

  // Cleanup on disconnect - remove connection from all rooms
  removeAllRooms(connectionId: ConnectionId): void {
    const userRooms = this.roomsForConnection.get(connectionId);
    if (userRooms) {
      for (const roomId of userRooms) {
        this.leave(connectionId, roomId);
      }
    }
  }
}
```

**Key characteristics:**
- Pure data structure - no WebSocket knowledge
- Tracks by ConnectionId (not WsClient objects)
- Inverse index enables efficient cleanup on disconnect
- Supports multiple connections per user (each tab has own ConnectionId)

**Add logging:** Consider adding scoped logging for join/leave operations (extract pattern from v1's ScopedLogger if needed).

**Add validation:** Consider runtime validation - ensure connectionId/roomId are present, log warnings for edge cases.

### Step 3: Implement WS Server

**File:** `apps/backend/src/ws/server.ts`

**Goal:** Create type-safe WebSocket server that integrates with Fastify.

**Key insight:** V2 demo's `createWSServer` is standalone. We need to adapt it for Fastify's plugin-based WebSocket handling.

**Approach:**
```ts
import type { WebSocket } from 'ws';
import { RoomManager } from './room-manager';
import type {
  HandlerMapWithCtx,
  ConnectionId,
  BroadcastOptions
} from './types';
import type { ClientMessage, ServerMessage } from '@protocol/...';

// WsClient internal representation
type WsClient = {
  id: ConnectionId;
  userKey: string;
  ws: WebSocket;
  // TODO: Add scoped logger
};

// Server config
type WSServerConfig<TIncoming, TOutgoing, TContext, TConnectionContext> = {
  handlers: HandlerMapWithCtx<TIncoming, TContext>;
  createContext: (connectionContext: TConnectionContext, ws: WebSocket) => TContext;
  getUserKey: (connectionContext: TConnectionContext) => string; // used for sendToUser()
  onDisconnect?: (context: TContext) => void;
  encode?: (msg: TOutgoing) => string;
  decode?: (raw: string) => TIncoming;
};

// Server instance (what bootstrap uses)
export type WSServerInstance<TOutgoing> = {
  handleConnection(ws: WebSocket, connectionContext: any): void;
  broadcast(message: TOutgoing, opts?: BroadcastOptions): void;
  broadcastToRoom(roomId: string, message: TOutgoing, opts?: BroadcastOptions): void;
  sendToUser(userKey: string, message: TOutgoing): void;
  rooms: RoomManager;
};

export function createWSServer<
  TIncoming extends { type: string },
  TOutgoing,
  TContext,
  TConnectionContext
>(
  config: WSServerConfig<TIncoming, TOutgoing, TContext, TConnectionContext>
): WSServerInstance<TOutgoing> {
  const { handlers, createContext, getUserKey, onDisconnect, encode, decode } = config;

  const clients = new Map<ConnectionId, WsClient>();
  const roomManager = new RoomManager();

  // Default encode/decode
  const encodeMsg = encode || ((msg: TOutgoing) => JSON.stringify(msg));
  const decodeMsg = decode || ((raw: string) => JSON.parse(raw) as TIncoming);

  function handleConnection(ws: WebSocket, connectionContext: TConnectionContext) {
    const context = createContext(connectionContext, ws);
    const clientId = context.connectionId;

    // Create and store client
    const client: WsClient = {
      id: clientId,
      userKey: getUserKey(connectionContext),
      ws,
    };
    clients.set(clientId, client);

    // Handle incoming messages
    ws.on('message', async (raw: WebSocket.RawData) => {
      try {
        // Fastify passes Buffer | ArrayBuffer | Buffer[] | string. Normalise before decoding.
        const rawString =
          typeof raw === 'string'
            ? raw
            : Array.isArray(raw)
              ? Buffer.concat(raw).toString('utf8')
              : Buffer.isBuffer(raw)
                ? raw.toString('utf8')
                : Buffer.from(raw).toString('utf8');
        const message = decodeMsg(rawString);
        const handler = handlers[message.type];

        if (!handler) {
          console.warn(`No handler for message type: ${message.type}`);
          return;
        }

        await handler(message.payload, context);
      } catch (error) {
        console.error('Error handling message:', error);
        // TODO: Send error message back to client?
      }
    });

    // Handle disconnect
    ws.on('close', () => {
      roomManager.removeAllRooms(clientId);
      clients.delete(clientId);
      onDisconnect?.(context);
    });

    ws.on('error', (error) => {
      console.error('WebSocket error:', error);
      roomManager.removeAllRooms(clientId);
      clients.delete(clientId);
    });
  }

  function broadcast(message: TOutgoing, opts?: BroadcastOptions) {
    const encoded = encodeMsg(message);
    for (const [id, client] of clients) {
      if (opts?.excludeConnectionId && id === opts.excludeConnectionId) {
        continue;
      }
      if (client.ws.readyState === WebSocket.OPEN) {
        client.ws.send(encoded);
      }
    }
  }

  function broadcastToRoom(roomId: string, message: TOutgoing, opts?: BroadcastOptions) {
    const members = roomManager.getMembers(roomId);
    const encoded = encodeMsg(message);

    for (const connectionId of members) {
      if (opts?.excludeConnectionId && connectionId === opts.excludeConnectionId) {
        continue;
      }
      const client = clients.get(connectionId);
      if (client && client.ws.readyState === WebSocket.OPEN) {
        client.ws.send(encoded);
      }
    }
  }

  function sendToUser(userKey: string, message: TOutgoing) {
    const encoded = encodeMsg(message);
    // Find all connections for this user
    for (const client of clients.values()) {
      if (client.userKey === userKey && client.ws.readyState === WebSocket.OPEN) {
        client.ws.send(encoded);
      }
    }
  }

  return {
    handleConnection,
    broadcast,
    broadcastToRoom,
    sendToUser,
    rooms: roomManager,
  };
}
```

**Key characteristics:**
- Generic over message types and context
- Fastify calls `handleConnection` for each new connection
- Server owns client map, RoomManager tracks membership
- Clients store a simple `userKey` so the transport stays app-agnostic
- Broadcasting methods support multi-tab (excludeConnectionId)

### Step 4: Implement Server Bridge

**File:** `apps/backend/src/ws/server-bridge.ts`

**Goal:** Create the wsBridge singleton that domain ws-effects will use.

```ts
import type { ServerMessage } from '@protocol/...';
import type { WsBridge, BroadcastOptions, ConnectionId } from './types';
import type { WSServerInstance } from './server';

class ServerBridge implements WsBridge {
  private transport: WSServerInstance<ServerMessage> | null = null;

  init(transport: WSServerInstance<ServerMessage>) {
    if (this.transport) {
      throw new Error('ServerBridge already initialized');
    }
    this.transport = transport;
  }

  private getTransport() {
    if (!this.transport) {
      throw new Error('ServerBridge not initialized. Call init() first.');
    }
    return this.transport;
  }

  broadcast(message: ServerMessage, opts?: BroadcastOptions): void {
    this.getTransport().broadcast(message, opts);
  }

  broadcastToRoom(roomId: string, message: ServerMessage, opts?: BroadcastOptions): void {
    this.getTransport().broadcastToRoom(roomId, message, opts);
  }

  sendToUser(userKey: string, message: ServerMessage): void {
    this.getTransport().sendToUser(userKey, message);
  }

  get rooms() {
    return {
      join: (roomId: string, connectionId: ConnectionId) => {
        this.getTransport().rooms.join(connectionId, roomId);
      },
      leave: (roomId: string, connectionId: ConnectionId) => {
        this.getTransport().rooms.leave(connectionId, roomId);
      },
      getMembers: (roomId: string) => {
        return this.getTransport().rooms.getMembers(roomId);
      },
    };
  }
}

// Export singleton instance
export const wsBridge = new ServerBridge();
```

**Key characteristics:**
- Lazy initialization pattern (throws if used before init)
- Clean interface matching what domain ws-effects expect
- Module-level singleton (effectively global but explicit init)

### Step 6: Create Bootstrap

**File:** `apps/backend/src/ws-server-bootstrap.ts`

**Goal:** Wire all domain handlers together and initialize the WS server.

```ts
import { createWSServer } from './ws/server';
import { wsBridge } from './ws/server-bridge';
import type { HandlerMapWithCtx } from './ws/types';
import type { ClientMessage, ServerMessage } from '@protocol/...';
import type { User } from '@/types/user';
import type { AppHandlerContext } from '@/ws-handler-context';

// Import all domain handlers
import { handlers as chatHandlers } from './domains/chat/handlers';
import { handlers as matchmakingHandlers } from './domains/matchmaking/handlers';
import { handlers as gameplayHandlers } from './domains/gameplay/handlers';
import { handlers as systemHandlers } from './domains/system/handlers';

// Merge all domain handlers into single map
const mergedHandlers: HandlerMapWithCtx<ClientMessage, AppHandlerContext> = {
  ...chatHandlers,
  ...matchmakingHandlers,
  ...gameplayHandlers,
  ...systemHandlers,
} satisfies HandlerMapWithCtx<ClientMessage, AppHandlerContext>;

// Helper to generate connection IDs
function generateConnectionId(): string {
  // TODO: Replace with a real ID generator (uuid / nanoid) during implementation
  return `client-${Math.random().toString(36).slice(2, 11)}`;
}

export function setupWebSocketV2() {
  // Create WS server with typed config
  const wsServer = createWSServer<
    ClientMessage,
    ServerMessage,
    AppHandlerContext,
    User
  >({
    handlers: mergedHandlers,
    createContext: (user, ws) => ({
      userId: user.id,
      connectionId: generateConnectionId(),
    }),
    getUserKey: (user) => user.id, // stable identifier used by sendToUser()
    onDisconnect: (context) => {
      console.log(`Client disconnected: ${context.connectionId}`);
    },
  });

  // Initialize bridge
  wsBridge.init(wsServer);

  return wsServer;
}
```

**Key characteristics:**
- Merges all domain handlers upfront
- Uses `satisfies` for compile-time handler completeness check
- Creates context from authenticated user (Fastify provides this)
- Initializes wsBridge singleton

### Step 7: Update Main Entry Point

Update to initialize v2 WS server and wire to Fastify.

```ts
import Fastify from 'fastify';
import websocket from '@fastify/websocket';
import { setupWebSocketV2 } from './ws-server-bootstrap';

const fastify = Fastify({ logger: true });

// Register websocket plugin
await fastify.register(websocket);

// Setup v2 WS server
const wsServer = setupWebSocketV2();

// WebSocket route
fastify.get('/ws', { websocket: true }, (connection, req) => {
  // Extract authenticated user from request
  const user = req.currentUser; // Assumes auth middleware sets this

  if (!user) {
    connection.socket.close(1008, 'Unauthorized');
    return;
  }

  // Let v2 server handle this connection
  wsServer.handleConnection(connection.socket, user);
});

// Start server
await fastify.listen({ port: 3000 });
```

**Key points:**
- Fastify extracts `req.currentUser` (from existing auth middleware)
- v2 server's `handleConnection` receives user + socket
- Keep v1 routes/setup for now (parallel operation during transition)
