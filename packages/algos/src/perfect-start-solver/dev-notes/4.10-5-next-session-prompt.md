## Where things stand

- Session 1 built the oracle (exhaustive enumerator) — ground truth for "at these lane lengths, does any valid decomposition exist?"
- Session 2 prototyped two cheap heuristics — **face projection** (filter) and **plain greedy longest-path** (constructor) — and evaluated them against the oracle on a 7-board × 4-seed × 3-profile matrix under two blob configurations.
- Headline numbers (reach-more blob config): face projection 100% precision / 76% recall in this matrix; plain greedy 88% recall. Failures cluster on two boards with clean explanations.
- The biggest qualitative finding was that our random-walk blob generator produces shapes no real solver would enumerate. "Reach-more" blobs (longer per-path reach) flipped most oracle-fails to feasible with no algorithmic change. Real prefix sets would likely spread wider still.
- Code: `packages/algos/src/perfect-start-solver/custom-algo-2/lane-decomp/` (`face-projection.ts`, `greedy-longest-path.ts`, `evaluate-heuristics.ts`).

## What's on the table for session 3

Session 2 findings §7 lists candidate directions. In rough priority order:

1. **Face-projection-seeded greedy** — use the face projection depth map to order the greedy DFS. Expected to close most `pocket-11x11` cases cheaply. Pure pipelining, no new algorithmic ideas.
2. **Length-aware max-flow filter** — a second filter tier that could catch chute-collision cases face projection misses (`tight-corner-1` medium/long is the canonical example). Still cheap.
3. **Realistic prefix blobs** — replace the random-walk generator with hand-picked or prefix-enumerator output. Biggest validity lift; the current blobs are the main threat to how much we can trust session 2's numbers.
4. **Single-lane backtracking in greedy** — philosophically closer to "good enough" than randomization, would likely close the pure-greedy ceiling.

Also open: methodology improvements (frontier size in CSV schema, blob generator diversification, RNG collision cleanup from session 1).
