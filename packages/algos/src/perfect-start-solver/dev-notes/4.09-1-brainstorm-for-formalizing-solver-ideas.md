# Formalizing recent ideas into a next-gen solver candidate

Brainstorm session exploring how several recent research threads might combine into a next-gen solver. The key threads:

- **Path-prefixes** (research-spike-1, session 3.23-2): Near-general prefix sets may resolve all inter-burst spatial conflicts in a small search space.
- **Burst-chain equivalence** (explore-landscape, sessions 1-4): Many burst sequences reach the same abstract state. In corridors, this gives massive collapse (500,000x for 4-corridor) and efficient DAG traversal.
- **Lane decomposition** (session 4 future directions + this brainstorm): Decompose real boards into corridor-like structures to bridge the gap between the two threads above.

The central hypothesis: prefix sets handle the near-general geometry (inter-burst conflicts, overlap routing), which produces a lane structure that corridor-style equivalence can exploit for the remaining search space.

**Key design tradeoff — prefix depth:** Prefix depth is a tuning parameter that controls the split of work between the near-region (prefix enumeration) and mid-region (lane decomposition / corridor model). Deeper prefixes mean more prefix enumeration work, but a simpler mid-region — fewer bursts extend beyond the prefix, suffixes are shorter, and lane decomposition is easier. Shallower prefixes are cheaper to enumerate, but push more complexity into the mid-region. The goal is to find the depth that minimizes total work across both phases. This balance point may vary by board geometry.

An alternative path worth keeping in mind: instead of lane decomposition, find a compact abstract state representation directly — some summary of owned territory that determines future burst costs on arbitrary boards, analogous to `(tick, army, frontier[])` in the corridor model. Lane decomposition and compact state discovery may converge (if boards consistently decompose into lanes, then frontier-per-lane IS the compact state), but they could also lead to different insights. This doc focuses on the lane decomposition path since it builds more directly on the concrete results we have.

## 1. Near-region / prefix-path characteristics

**What we're trying to answer:** How large is the prefix-set search space, and what controls its size?

**What we know (from prefix theory doc + session 3.23-2):**

- Prefix candidates = all non-backtracking paths from the general up to depth D (3-4)
- At depth D on a degree-4 general: bounded by ~4 × 3^(D-1) candidates (each step has at most 3 non-backtracking choices). Depth 3: ~36. Depth 4: ~108. Mountains and edges reduce this.
- A prefix set = one prefix per burst slot, mutually compatible
- Compatibility = zero-overlap bursts share no tiles; overlap-K bursts have first K tiles in covered set
- Conjectured: tens to low hundreds of viable prefix sets per board
- L1 partitioning in the current solver is effectively depth-1 prefix

**Key sub-questions:**

- What are the actual prefix candidate counts on real boards at depth 3, 4, 5? (Research-spike-1 may have data)
- How many compatible prefix sets exist for typical burst counts (4-6 bursts)? How sensitive is this to depth D?
- How does overlap interact? Each additional overlap burst couples the prefix set, but does it meaningfully shrink the count, or does it add more valid combos than it prunes?
- Is there a clean incremental enumeration (build prefix sets burst-by-burst, pruning early), or do you need to generate-and-filter?
- What fraction of geometrically valid prefix sets are "good" (tips open into usable space)?

## 2. Region definitions

**What we're trying to answer:** Where does each region start and end, and what determines the boundaries?

**Near-region:**

- Contains all tiles that *any* burst might need to re-traverse (overlap territory) plus the tiles where bursts compete for directional commitment
- Lower bound on size: overlap determines the minimum. Max overlap per burst is typically 0-4 tiles. But the near-region is probably larger than just the overlap zone — even zero-overlap bursts compete for the tiles right next to the general
- Candidate definition: all tiles within distance D of the general, where D = prefix depth. This is simple and distance-based. But is distance the right criterion, or is it more about the board topology? On an open board, distance 3 covers ~28 tiles. On a board with a wall next to the general, distance 3 might only cover 10.
- A tighter definition might be: the union of all prefix paths across all viable prefix sets. That's topology-aware but circular (depends on knowing the prefix sets first)

**Mid-region:**

- Tiles reachable by at least one burst's suffix but not in the near-region
- Inner boundary: the near-region boundary (distance D from general, roughly)
- Outer boundary: maximum effective burst reach. For 24-capture in 50 ticks, the longest burst is ~12-13 tiles. Subtract prefix depth (3-4) and the suffix extends ~8-10 tiles beyond the near-region edge.
- Thins progressively: at distance 5-8 from general, maybe 2-3 bursts are active. At distance 10+, typically only the longest burst. This progressive thinning is important — it means the mid-region decomposition gets *easier* with distance.

**Far-region:**

- Unreachable within the tick budget. Hard upper bound: distance 16 from general (single burst using all 50 ticks). Practical bound: ~13 for any solution with multiple bursts. Safely ignored.

**Open sub-question:** Is the near/mid boundary sharp or fuzzy? With a fixed prefix depth D, it's sharp (distance D). But the "right" prefix depth might vary by direction on an asymmetric board — one direction might be a corridor (depth 2 is enough) while another is open (depth 4 needed). Variable-depth prefixes per burst would complicate enumeration but might give tighter regions.

## 3. Burst-to-region segmentation

**What we're trying to answer:** For each burst in a typical pattern, which region(s) does it span?

**Starting from the timing model:**

- For 24 captures in 50 ticks, typical patterns: [12,7,3,2], [11,8,3,2], [10,7,4,3], [9,7,5,3], etc.
- Bursts are descending by capture count. The overlap adds traversal length but not captures.

**Segmentation by burst rank (longest to shortest):**

| Burst rank | Typical capture range | Near-region tiles (prefix) | Mid-region tiles (suffix) | Notes |
|---|---|---|---|---|
| 1st (longest) | 9-13 | 3-4 | 5-10 | Deepest penetration. Suffix dominates. |
| 2nd | 5-8 | 3-4 | 1-5 | Moderate suffix. |
| 3rd | 2-4 | 2-4 | 0-1 | Mostly or entirely prefix. |
| 4th+ | 1-3 | 1-3 | 0 | Entirely prefix. |

**This supports the hypothesis that bursts 3+ are fully handled by the prefix sub-problem.** The mid-region decomposition only needs to handle 1-2 bursts (occasionally 3).

**Sub-questions:**

- Nail down the actual distribution from the timing table. For every valid timing entry at 24 captures / 50 ticks, what are the burst lengths? What's the max 2nd-burst length, 3rd-burst length?
- How does overlap shift this? A burst with overlap K has K tiles in the near-region (retracing) + its fresh captures. So a length-7 burst with overlap-3 has 3 near-region tiles + 4 new tiles. The suffix is shorter.
- Are there edge cases where a short burst has a long suffix? (Seems unlikely with descending patterns, but worth checking.)

## 4. Mid-region decomposition / search

**What we're trying to answer:** Given a prefix set and the board beyond the prefix tips, how do we efficiently characterize the suffix-space for the 1-2 bursts that extend into it?

### Lane decomposition as the high-level framing

The promising direction: decompose the mid-region into **lanes** — corridor-like structures extending from each prefix tip outward — so that the corridor model's equivalence machinery (from the explore-landscape sessions) can be applied.

A valid lane decomposition needs:
- **Non-overlapping lanes** — each tile belongs to at most one lane. This guarantees lane independence: advancing in one lane can't affect costs in another (the only shared resources are army and ticks at the general, which the corridor model already handles).
- **Non-backtracking** — each lane is a path a burst can advance through without backtracking.
- **Sufficient length** — each lane is long enough for the burst(s) assigned to it. We don't need full coverage of the mid-region — just a small number of lanes (likely 1-4 for max-tick=50) of sufficient length for the bursts that reach the mid-region.

If we can produce lane decompositions that satisfy these properties, the mid-region search reduces to a parameterized N-corridor problem — which we already know how to solve efficiently via DAG traversal.

**How to actually produce valid lane decompositions is the core unsolved piece.** Some early ideas from brainstorming (not exhaustive — there may be better approaches we haven't thought of yet):

- **Voronoi-like partitioning:** Assign each mid-region tile to the nearest prefix tip, creating natural lane territories. Related to the explore-landscape session 4 idea of dividing open boards into quadrants from spine bursts along cardinal directions.
- **Width-based analysis:** Measure the "width" of the reachable region at each distance from each tip. Wider regions might support multiple sub-lanes. The challenge is defining "width" precisely when paths can curve.
- **Capacity bounds as a fast filter:** BFS from each prefix tip, count reachable tiles excluding other lanes' territory. Cheap feasibility check — might be sufficient to prune bad prefix sets before doing more precise lane construction.
- **Geometry-guided:** On constrained boards (corridors, walls), the lane structure may be forced by the terrain. On open boards, more freedom but also less constraint to model.

The right approach may depend on board geometry. Constrained boards (where the solver is slowest) may have near-obvious decompositions. Open boards (where the solver is already fast) may need more work but also tolerate approximation.

**Key sub-questions:**

- When prefix tips point in different directions (≥ 90° apart), their mid-regions are very likely disjoint and lane independence holds naturally. When tips point in similar directions (narrow board funneling them together), lanes might overlap. How do we detect and handle this?
- Only 1-2 bursts (occasionally 3) extend into the mid-region (see #3 for precise burst-to-region segmentation). Is that small enough that even simple or brute-force approaches to decomposition are tractable?
- Does the decomposition need to be exact, or is an approximate decomposition (with some error in lane length estimates) good enough for the corridor model to still find optimal or near-optimal solutions?

## 5. Near-to-corridor interface

**What we're trying to answer:** Given a prefix set and a characterized mid-region, what's the formal input to the corridor model?

**The corridor DAG currently takes:**

- Number of corridors (N)
- Max ticks
- Army growth rate

And implicitly assumes each corridor is infinite-length and width-1.

**What we need to extend it with, per lane:**

- **Max length** — the lane has finite capacity. Frontier can't exceed this.
- **Entry overhead** — fixed tick cost to reach this lane from the general (the overlap portion of the prefix). This shifts the effective tick budget for that lane.
- **Possibly: variable capacity by depth** — if the lane narrows at some distance, the effective length might be shorter than the raw tile count suggests.

**Sub-questions:**

- Can the corridor DAG be cleanly parameterized for finite-length heterogeneous corridors? The state would become `(tick, army, frontier[])` where each frontier has a per-lane cap. This probably doesn't change the algorithm structure, just adds bounds checks.
- Entry overhead: is it a flat per-burst cost, or does it vary by burst? For a given prefix set, each lane has a fixed overhead (the overlap length to reach it). Different bursts using that lane always pay the same overhead. This should be clean.
- Does the corridor model need to know which bursts are "near-region only" (no suffix)? Or can those be folded in as zero-length lanes? The latter would be cleaner — every burst has a lane, some lanes just have max-length = 0 after the prefix.

## 6. Saved tiles

**What we're trying to answer:** How do reserved final-burst tiles interact with the prefix/region framework?

**Context from session 4:** Optimal solutions often reserve 1-3 uncaptured tiles adjacent to the general for a small final burst in ticks ~45-49. Without this, you can't use the last few ticks productively.

**Interactions:**

- Saved tiles are in the near-region (adjacent to the general), but must be excluded from prefix paths. They constrain which prefix sets are valid.
- They effectively create a tiny "reserved lane" — length 1-3, zero overhead, used only for the final burst. This maps naturally to the corridor model as an additional short lane.
- On boards where the general has few open neighbors (≤ 3), saving a tile costs a direction — one fewer prefix slot available. This could significantly constrain prefix sets.
- The corridor model's "free threshold" finding (total frontier ≤ 2 collapses to a single state) might be related — saved tiles represent frontier = 0 in a lane that's deliberately held back.

**Sub-questions:**

- How many tiles need to be saved? Is it always 1-3, or can it be more on some boards?
- Does the saved-tile decision need to be made during prefix enumeration, or can it be deferred? If it's just "reserve one neighbor of the general," it's a prefix-level decision. If it's more complex (reserve a specific 2-3 tile path), it might need more work.
- Possible approach: saved tiles might just be one of the short prefix paths in the prefix set — a burst that's part of the normal prefix enumeration but happens to be reserved for late in the round. If so, saved tiles aren't a separate concern at all; the prefix set + timing model handle them naturally.
- On degree-3 boards (general against a wall), saving a tile costs 33% of available directions. How much does this constrain the prefix space?
