# Session 4: Tip Scorer + Prefix-Set Generator — First Empirical Loop

Fourth session in the mid-region lane decomposition thread. First empirical run of the prefix/lane reframe end-to-end: built the scoring → generator → comparison loop outlined in [session 3 §7](4.10-7-session-3-notes.md), and got one concrete signal plus one ablation finding that reshapes where the scoring work should go.

## 1. Session arc

- Scoped a linked chunk: per-tile tip scorer → dumb prefix-set generator → comparison harness against session 2's 7-board matrix. Deliberately dumb v1 on all three pieces to close the end-to-end loop before investing in anything cleverer
- Built everything, plus two CLI visualizers (one for prefix-set dumps, one for standalone board rendering), iterated with the dump tools until the generator stopped producing degenerate outputs
- First comparison at profile `[8,5,3]` surfaced clear signal on one board (`tight-corner-1`) and nothing elsewhere
- Dispatched an opus sub-agent for a targeted 4×4×4 sweep (profile × scorer variant × board) to probe whether the signal was real and whether the scorer's complexity was doing work

## 2. What we built

- **New modules:** `starting-region/tip-scorer.ts` (v1 per-tile scorer), `custom-algo-2/prefix-gen/{generate,compare-blob-sources}.ts` (generator + comparison runner), two CLIs: `prefix-gen/dump-prefix-sets.ts` and `utils/render-board-cli.ts`
- **"Dumb v1 on every piece" was the deliberate choice.** Scorer is a linear combo; generator is a flat DFS enumerate-and-filter; comparison runner is a drop-in blob-source swap. The goal was closing the scorer → generator → harness loop end-to-end before investing in anything cleverer — so that downstream pressure (the comparison numbers) could tell us which pieces actually needed sophistication
- **Heavy infra reuse.** Built on top of session 3's `starting-region/` annotations (nothing new added there), reused session 2's lane-decomp oracle + blob types verbatim (the comparison runner is a new blob source feeding an unchanged harness), CLIs built on the existing `typed-command` pattern
- **Tooling alongside code as a workflow pattern.** Extended `starting-region/debug-dump.ts` with a scorer heatmap pane; built `dump-prefix-sets` CLI for generator output inspection; built `render-board-cli` as a reusable board visualizer not tied to this session's work. The tight iteration loop on overlap-budget defaults and the sub-agent sweep were both only possible because the visualizers were in place
- **Overlap semantic** for the generator: single overall budget `(sum path lengths) − |union|`, default `(K−1)·(L−1)` — generous on purpose, relies on scoring pressure + heap dedup-by-union-mask to filter degenerate permutations. Chose simpler-over-richer here to avoid duplicating research-spike-1's per-burst pattern without a reason to

## 3. Signal — `tight-corner-1` gen beats rw, everywhere we tested it

`3.21-real-board-tight-corner-1` is [session 2](4.10-4-lane-decomp-session-2-summary.md)'s "genuinely hard" case and the reframe's canonical proof-of-concept target.

Random-walk blobs are **0/4 feasible** on this board across all 4 session-2 seeds, at every profile tested. Generated prefix-set blobs find feasible blobs on it under **every** tested profile × scorer variant. Specific gen-feasible counts on `tight-corner-1` (baseline scorer, prefix-lengths 4–7, top-K=5 per length):

| profile | gen feasible |
|---|---|
| `6,4,3` | 8/15 |
| `8,6,4` | 6/15 |
| `5,3,3,2` | 5/15 |
| `10,7,4,2` | 4/15 |

Monotonic degradation as the profile gets harder, never collapses. First concrete evidence the reframe isn't just a session-3 thought experiment.

Full sweep numbers in `custom-algo-2/prefix-gen/output/` (gitignored, not committed).

## 4. Ablation finding — tip-aggregated top-K doesn't extract signal from divergence/AP on this matrix

The sweep ablated the scorer: `baseline` (α=2, β=3), `no-AP` (β=0), `no-div` (α=0), `depth-only` (α=β=0).

- **`no-AP` is bit-identical to `baseline`** on `tight-corner-1` across all 4 profiles. At top-K=5 on this matrix, the articulation penalty contributes zero useful signal
- **`depth-only` tracks `baseline` within ±1** across all 4 profiles. Pure `rayDepth` is doing ~all the work
- **`no-div` is *worse* than `depth-only`** on 3/4 profiles. Adding the AP penalty without the divergence bonus is actively counterproductive — AP is only "harmless" when paired with divergence

**Narrow claim:** under tip-aggregated top-K selection at K=5 on this 4-board matrix, `rayDepth` alone is nearly as good as the full v1 formula. This does **not** mean "drop divergence and AP" categorically — we only tested one way of consuming those signals. Whether they contribute under richer aggregations (set-level blob/frontier features) or on harder boards is unprobed.

## 5. Matrix-too-narrow

Only `tight-corner-1` showed a gen-vs-rw gap. The other 3 sweep boards (`corner-13x13`, `scattered-pockets-13x13`, `sparse-mtns-11x11`) were all 8/8 random-walk feasible at every profile — zero headroom to distinguish scorer variants. Any future ablation or matrix sweep needs boards hard enough that rw actually fails, otherwise we're measuring nothing.

## 6. Known limitations / loose ends

- **Per-tip scoring is noisy at the top**: on `tight-corner-1` at L=5, rank 1 is feasible, rank 2 isn't, rank 4 is again. Matches the "joint quality is not local" tension from the [reframe doc](4.10-6-prefix-sets-and-lanes-reframed.md)
- **`scattered-pockets-13x13` gen-L4**: same single prefix-set produced across all 16 variant combos, same oracle miss every time. Not worth chasing until the generator produces more diversity on degenerate-geometry boards
- **Top-K=5 as a ceiling**: small cut means score ordering barely matters within the retained set. Larger K might reveal differences that top-5 hides
- **Scorer complexity question is genuinely open**, not closed: the ablation showed narrow non-effect, not broad uselessness

## 7. Pointers for next session

**Must-do first (methodology):**

1. **Broader matrix sweep with harder boards.** Add boards (and/or profiles) that actually fail for random-walk so we have headroom to distinguish scorer variants on more than one point. Sweep parameters TBD — worth a focused discussion before running

**Open brainstorm topics** (not committed scoped work, next-session discussion material):

- **Prefix-set-level scoring probe** — test whether the v1 scorer's divergence/AP signals become load-bearing under richer aggregations: sum over whole blob, frontier-quality sum, spatial spread of tips, etc. Cheap to try once the broader matrix exists
- **Why didn't divergence and AP help?** — theoretical discussion of why the two low-signal pieces didn't contribute on the boards tested, and what board conditions would exercise them (e.g., tiles with similar depth but different directional optionality for divergence; high-depth AP tiles for the penalty)
- **New tip-scorer signals beyond depth/divergence/AP** — what other cheap per-tile annotations could contribute that we haven't tried yet
- **Joint prefix-set quality more broadly** — scoring the *set* rather than aggregating per-tip scores; addresses the rank-noise issue directly
