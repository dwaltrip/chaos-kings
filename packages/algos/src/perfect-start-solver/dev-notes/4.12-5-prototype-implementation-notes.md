# Prototype implementation notes — custom-algo-2

Notes from building the initial end-to-end solver prototype (2026-04-12). The implementation followed the [design doc](4.12-2-prototype-solver-design.md) and [implementation sketch](4.12-3-implementation-sketch.md) closely — no significant deviations. See those docs for architecture, conventions, deferred work, and open questions.

## What was built

- `utils/find-path.ts` — shared DFS path finder, extracted from `greedy-longest-path.ts`
- `custom-algo-2/prefix-pool.ts` — wraps prefix-gen, iterates burst-count x path-length configs
- `custom-algo-2/burst-mapper.ts` — recursive burst-to-prefix-path assignment with overlap verification
- `custom-algo-2/lane-builder.ts` — greedy DFS lane construction with M! orderings
- `custom-algo-2/assembler.ts` — stitches prefix + lane paths, validates timing
- `custom-algo-2/solve.ts` — orchestrator
- `custom-algo-2/run.ts` — CLI runner
- General-exclusion convention applied to `prefix-gen/generate.ts` + research scripts

## Implementation details beyond the sketch

- **Assembler lane mapping:** Uses `Map<number, PathResult>` keyed by burst index to handle the sparse relationship between assignments and lanes (only mid-region bursts have lanes). Minor wiring detail.
- **`findPath` return type:** Returns `PathResult` (tiles + mask), structurally identical to the existing `Lane` type. No adapter code needed.
- **`SolveStats`:** Added a stats struct to the orchestrator for diagnostic output (prefix sets generated, timing entries checked, mappings attempted, lane attempts).

## Known naive choices in the prototype

All intentional for first-pass simplicity — the design doc and implementation sketch discuss these in detail.

- **No timing entry ranking or indexing** — flat iteration over all entries per prefix set. Volume balloons at lower targets (~5.7K at 24, ~50K at 23, ~168K at 22).
- **Mapper returns all assignments eagerly** — full array, not iterator. Could be a bottleneck if a (prefix set, timing entry) pair produces many valid assignments.
- **No failure strategy beyond lowering target** — the design doc outlines a 3-tier escalation (expand pool, full enumeration, lower target); only tier 3 is implemented.
- **Uniform prefix lengths per config** — `generatePrefixPool` uses `Array(K).fill(L)`, no mixed-length configs.
- **Prefix pool pre-computed upfront** for all overlap values up to the budget, rather than on-demand.
- **Top-K scoring only** — no full prefix enumeration fallback (first priority follow-up per design doc).
