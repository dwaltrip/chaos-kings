# L1 Integration Sketch

Session 3.21-1. Plan for integrating L1 neighbor partitioning into solver-v3.

## Goal

Replace flat candidate iteration in `searchGrouped` with partitioned search by starting neighbor. Reduce per-call overhead vs the experiment implementation. No API changes.

## Data structures

### NeighborInfo

Bundle per-neighbor data into a struct instead of parallel arrays. Keeps index coupling explicit and makes L3 integration trivial (just add `blankMasks: bigint[]`).

```typescript
interface NeighborInfo {
  tile: number;    // tile index of this neighbor
  bit: bigint;     // precomputed 1n << BigInt(tile)
}
```

Computed once during setup:
```typescript
function getNeighborInfos(board: FlatBoard, generalPos: number): NeighborInfo[] {
  const infos: NeighborInfo[] = [];
  for (const dir of DIRECTIONS) {
    const next = Board.neighbor(board, generalPos, dir);
    if (!Board.isValidIndex(board, next)) continue;
    if (board.types[next] === TileType.MOUNTAIN) continue;
    infos.push({ tile: next, bit: 1n << BigInt(next) });
  }
  return infos;
}
```

### PartitionedEntries

The experiment used `Map<number, Map<number, PathEntry[]>>` (moveLen → neighbor → candidates). For production, use arrays indexed by neighbor position in `NeighborInfo[]`:

```typescript
// For each moveLen, candidates grouped by which neighbor they start from
type PartitionedEntries = Map<number, PathEntry[][]>;
// partitioned.get(moveLen)?.[neighborIdx] → PathEntry[]
```

Key differences from experiment:
- **Arrays instead of inner Map** — neighbors are a small fixed set (2-4), array index is faster than Map lookup
- **Precomputed bits in `NeighborInfo`** — avoids `1n << BigInt(neighbor)` per recursive call (was the main per-depth overhead in experiment)

### Building partitioned entries

```typescript
function buildPartitionedEntries(
  entriesByLen: PathEntriesByLen,
  neighborInfos: NeighborInfo[],
): PartitionedEntries {
  // Build tile→index lookup
  const neighborIdx = new Map<number, number>();
  for (let i = 0; i < neighborInfos.length; i++) {
    neighborIdx.set(neighborInfos[i].tile, i);
  }

  const result: PartitionedEntries = new Map();
  for (const [len, entries] of entriesByLen) {
    const byNeighbor: PathEntry[][] = neighborInfos.map(() => []);
    for (const entry of entries) {
      const idx = neighborIdx.get(entry.tiles[0]);
      // All paths start from general — tiles[0] must be a neighbor.
      // Assert to catch silent data loss if path generation changes.
      if (idx === undefined) {
        throw new Error(`tiles[0]=${entry.tiles[0]} is not a neighbor of the general`);
      }
      byNeighbor[idx].push(entry);
    }
    result.set(len, byNeighbor);
  }
  return result;
}
```

### SearchContext

Pack static (per-solve) parameters into a context object. Only `entries`, `burstIdx`, and `coveredMask` change per recursive call. This also makes future additions (L3 masks, ordering heuristics) painless.

```typescript
interface SearchContext {
  partitioned: PartitionedEntries;
  neighborInfos: NeighborInfo[];
  blankTileMasks: bigint[];
  stats: SearchStats;
}
```

## Changes to searchGrouped

Current inner loop (lines 295-328):
```typescript
for (const [key, bucket] of buckets) {
  const candidates = entriesByLen.get(moveLen);
  for (const cand of candidates) { ... }
}
```

Becomes:
```typescript
for (const [key, bucket] of buckets) {
  const partitionsAtLen = ctx.partitioned.get(moveLen);
  if (!partitionsAtLen) continue;

  for (let ni = 0; ni < ctx.neighborInfos.length; ni++) {
    const nb = ctx.neighborInfos[ni];
    const neighborCovered = (coveredMask & nb.bit) !== 0n;

    // Zero-overlap: tiles[0] must NOT be covered → skip covered neighbors.
    // Overlap > 0: tiles[0] MUST be covered, because prefix overlap requires
    // contiguous coverage starting at tiles[0] (countPrefixOverlap invariant).
    if (overlap === 0 && neighborCovered) continue;
    if (overlap > 0 && !neighborCovered) continue;

    const partition = partitionsAtLen[ni];
    for (const cand of partition) {
      // ... same candidate checks as before
    }
  }
}
```

The partition skip is the filtering that gives the ~50% candidate reduction on degree-2 boards.

### blankNeighborCount from neighborInfos

Currently: `popcount(blankTileMasks[1] & ~coveredMask)` — bigint AND + NOT + popcount on the full dist-1 mask.

With `neighborInfos` available, compute directly:
```typescript
let blankNeighborCount = 0;
for (const nb of ctx.neighborInfos) {
  if ((coveredMask & nb.bit) === 0n) blankNeighborCount++;
}
```

Same result (dist-1 reachable tiles = general's non-mountain neighbors), avoids the heavy bigint ops.

## Changes to solveV3

Setup phase adds:
```typescript
const neighborInfos = getNeighborInfos(board, generalPos);
const partitioned = buildPartitionedEntries(entriesByLen, neighborInfos);
const ctx: SearchContext = { partitioned, neighborInfos, blankTileMasks, stats };
```

`entriesByLen` is still needed for:
- `buildTimingGroups` (checks `entriesByLen.has(m)` to filter timing entries)
- Burst-1 outer loop (`entriesByLen.get(group.burst1Moves)`)

But it is no longer passed into `searchGrouped`.

### Burst-1 is not partitioned

The burst-1 outer loop iterates flat candidates from `entriesByLen`. This is intentional: burst-1 starts from empty `coveredMask`, so no neighbor partitions can be skipped — all neighbors are uncovered, all partitions are relevant. Partitioning would add overhead with zero filtering benefit.

### buildSolution helper

Extract solution construction (currently duplicated in solver and experiments):
```typescript
function buildSolution(entry: TimingEntry, paths: PathEntry[], maxTicks: number): Solution {
  const moves = entry.captures.map((c, i) => c + entry.overlaps[i]);
  const burstSpecs: BurstSpec[] = entry.captures.map((c, i) => ({
    captures: c, moves: moves[i],
  }));
  let coveredMask = 0n;
  for (const p of paths) coveredMask |= p.mask;
  return {
    pattern: entry.captures,
    burstSpecs,
    burstInfos: getBurstInfosFromSpecs(burstSpecs, maxTicks)!,
    paths,
    coveredMask,
    totalCaptured: popcount(coveredMask),
  };
}
```

## What doesn't change

- All exported types and API surface (SolverResult, Solution, etc.)
- `buildTimingGroups`, feasibility functions, `bucketKey`
- Outer solve loop structure (capture targets, groups, burst-1 iteration)
- Path generation, timing table
