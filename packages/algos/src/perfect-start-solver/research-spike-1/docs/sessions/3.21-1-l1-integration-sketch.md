# L1 Integration Sketch

Session 3.21-1. Plan for integrating L1 neighbor partitioning into solver-v3.

## Goal

Replace flat candidate iteration in `searchGrouped` with partitioned search by starting neighbor. Reduce per-call overhead vs the experiment implementation. No API changes.

## Data structures

### PartitionedEntries

The experiment used `Map<number, Map<number, PathEntry[]>>` (moveLen → neighbor → candidates). For production:

```typescript
// Neighbors of the general (blank cardinal neighbors, typically 2-4)
// Computed once during setup
const neighbors: number[] = [...];          // e.g. [14, 32, 36, 54]
const neighborBits: bigint[] = [...];       // precomputed 1n << BigInt(n) for each

// Partition structure: array indexed by [neighborIdx], not by tile ID
// For each moveLen, candidates grouped by which neighbor they start from
type PartitionedEntries = Map<number, PathEntry[][]>;
// partitioned.get(moveLen)?.[neighborIdx] → PathEntry[]
```

Key differences from experiment:
- **Arrays instead of inner Map** — neighbors are a small fixed set (2-4), array index is faster than Map lookup
- **Precomputed `neighborBits`** — avoids `1n << BigInt(neighbor)` per recursive call (was the main per-depth overhead in experiment)
- **`neighborIndex` mapping** — need a lookup from tile ID → index in the neighbors array, used during partitioning

### Building partitioned entries

```typescript
function buildPartitionedEntries(
  entriesByLen: PathEntriesByLen,
  neighbors: number[],
): PartitionedEntries {
  // Build tile→index lookup
  const neighborIdx = new Map<number, number>();
  for (let i = 0; i < neighbors.length; i++) {
    neighborIdx.set(neighbors[i], i);
  }

  const result: PartitionedEntries = new Map();
  for (const [len, entries] of entriesByLen) {
    const byNeighbor: PathEntry[][] = neighbors.map(() => []);
    for (const entry of entries) {
      const idx = neighborIdx.get(entry.tiles[0]);
      if (idx !== undefined) {
        byNeighbor[idx].push(entry);
      }
      // entries whose tiles[0] isn't a neighbor of the general shouldn't exist
      // (all paths start from general, tiles[0] is first step = must be neighbor)
    }
    result.set(len, byNeighbor);
  }
  return result;
}
```

### Getting neighbors of general

```typescript
function getGeneralNeighbors(board: FlatBoard, generalPos: number): number[] {
  const neighbors: number[] = [];
  for (const dir of DIRECTIONS) {
    const next = Board.neighbor(board, generalPos, dir);
    if (!Board.isValidIndex(board, next)) continue;
    if (board.types[next] === TileType.MOUNTAIN) continue;
    neighbors.push(next);
  }
  return neighbors;
}
```

## Changes to searchGrouped

Current inner loop (lines 295-328):
```typescript
for (const [key, bucket] of buckets) {
  const candidates = entriesByLen.get(moveLen);
  for (const cand of candidates) { ... }
}
```

Becomes:
```typescript
for (const [key, bucket] of buckets) {
  const partitionsAtLen = partitioned.get(moveLen);
  if (!partitionsAtLen) continue;

  for (let ni = 0; ni < neighbors.length; ni++) {
    const neighborCovered = (coveredMask & neighborBits[ni]) !== 0n;
    if (overlap === 0 && neighborCovered) continue;   // zero-overlap: neighbor must be free
    if (overlap > 0 && !neighborCovered) continue;    // overlap: neighbor must be covered

    const partition = partitionsAtLen[ni];
    for (const cand of partition) {
      // ... same candidate checks as before
    }
  }
}
```

The partition skip is the filtering that gives the ~50% candidate reduction on degree-2 boards.

## Changes to solveV3

Setup phase adds:
```typescript
const neighbors = getGeneralNeighbors(board, generalPos);
const neighborBits = neighbors.map(n => 1n << BigInt(n));
const partitioned = buildPartitionedEntries(entriesByLen, neighbors);
```

These replace `entriesByLen` as the argument to `searchGrouped`. The outer burst-1 loop is unchanged (it iterates flat candidates).

## Signature change for searchGrouped

```typescript
function searchGrouped(
  partitioned: PartitionedEntries,   // was: entriesByLen
  neighbors: number[],               // new
  neighborBits: bigint[],            // new
  entries: EntryWithMoves[],
  burstIdx: number,
  coveredMask: bigint,
  blankTileMasks: bigint[],
  stats: SearchStats,
): SearchResult | null
```

`entriesByLen` is no longer needed inside search — partitioned entries fully replace it.

## What doesn't change

- All exported types and API surface
- `buildTimingGroups`, feasibility functions, `bucketKey`
- Outer solve loop structure (capture targets, groups, burst-1 iteration)
- Path generation, timing table
- The burst-1 outer loop still uses flat `entriesByLen` to get candidates (burst-1 is not partitioned — it's the loop that establishes the first covered mask)
