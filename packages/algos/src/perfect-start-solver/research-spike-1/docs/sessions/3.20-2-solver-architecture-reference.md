## High-level flow (`solveV3`)

1. Generate all paths from the general via DP (up to length 12+)
2. Precompute spatial distance masks for feasibility pruning
3. For each capture target (24 down to 15):
   - Generate all valid timing entries (burst patterns × overlap combos)
   - Group timing entries by burst-1 move length
   - For each burst-1 candidate path, run recursive grouped search
4. Return first valid solution found

## Timing entries & groups

**Building timing entries** (`timing-table.ts`):
1. `genDescendingPartitions(totalCaptures, maxBurst, maxBursts)` — all burst patterns in descending order (e.g. [12,7,3,2])
2. `expandOverlapCombos` — burst 0 always overlap=0; bursts 1..N try 0 to maxOverlapPerBurst
3. `simulateOneBurst` checks tick budget; entries sorted by total overlap ascending

**Grouping** (`buildTimingGroups`): groups by `entry.captures[0]` (burst-1 length), sorted descending (longest first). This is the ordering that group-ordering experiments would change.

## Path generation DP (`gen-paths.ts`)

Level-by-level BFS from general. At each step, extend tip by one cardinal neighbor that isn't a mountain and isn't already in the path (checked via bitmask). Non-backtracking, 4-connected, contiguous chains.

`buildPathEntries` strips the start tile, re-indexes by move length. Result: `PathEntriesByLen` = Map<length, PathEntry[]>.

Typical scale: length 12 on open-11x11 → ~178K paths.

## Inner search loop (`searchGrouped`)

Recursive backtracking, one burst per depth:

1. **Feasibility checks** (fast-fail):
   - `entryIsFeasibleNeighbors` — zero-overlap bursts remaining ≤ blank neighbors available
   - `entryIsFeasiblePerBurst` — each remaining burst has ≥ captures[i] blank tiles within reach distance
   - `entryIsFeasibleAggregate` — total remaining captures fit within reachable blanks
   - If ALL entries fail feasibility → prune branch

2. **Bucketing** — group feasible entries by `(moveLen, overlap)` tuple. Scan candidates once per unique bucket (amortization — don't rescan for every timing entry with same moveLen+overlap).

3. **Candidate filtering** (the hot loop):
   ```
   for each candidate path:
     if overlap === 0:
       if (cand.mask & coveredMask) !== 0n → skip  // any overlap = fail
     else:
       if popcount(cand.mask & coveredMask) !== overlap → skip
       if countPrefixOverlap(cand.tiles, coveredMask) !== overlap → skip
     // passed — recurse with newCovered = coveredMask | newTilesMask
   ```

**`coveredMask`**: bigint bitmask, bit i = 1 iff tile i claimed by any previous burst. All overlap checks are bitwise.

**`countPrefixOverlap`**: walks tiles[0..] counting how many leading tiles are in coveredMask. Returns -1 if overlap is non-contiguous (gap in prefix). Used to validate that overlap is a proper prefix.

## Current direction awareness

**Minimal.** The solver is board-agnostic until feasibility pruning.

What exists:
- `precomputeBlankTileDistMasks` — BFS from general up to dist 4, cumulative masks of reachable non-mountain tiles. Used in feasibility checks.
- `entryIsFeasibleNeighbors` — counts blank neighbors of general, ensures remaining zero-overlap bursts ≤ blank neighbors. Direction-aware in spirit.

What's missing:
- No partitioning of candidates by starting neighbor (`tiles[0]`)
- No group ordering by neighbor reach / feasibility heuristic
- No symmetry breaking (equivalent solutions through symmetric neighbors searched redundantly)
