# Session 3.20-3 LOG

**Date**: 2026-03-20 / 2026-03-21 (split across two sittings)

## What happened

1. **Implemented L2 experiment** — explicit burst→neighbor assignment without timing-entry grouping. Compared against baseline across all 28 boards.

2. **Result: negative.** L2-without-grouping is slower than L1 on every board. Same candidate reduction on corner boards but per-entry overhead from dropped grouping dominates. Severe regressions on edge-pocket-9x9 (0.39x) and pocket-11x11 (0.39x). Committed experiment + initial notes.

3. **Opus review** of experiment design and findings. Key critique: experiment was "designed backwards" — should have kept grouping and added assignment on top, per the theory doc's additive design. Also identified pocket-11x11 as a distinct failure mechanism (feasibility overhead, not duplicate scanning) and flagged redundant feasibility checks.

4. **Discussed results and review.** Confirmed L2+grouping collapses to L1 on degree-2 boards (no practical benefit on current hard boards). L2+grouping only helps on hard degree-3+ boards.

5. **Tested hard-degree3-9x9 board** (new board added to test suite). L1: 1.10x/53% reduction. L2: 0.88x/33% reduction. Board was too easy (~8ms) for meaningful timing, but L1 still showed improvement (1.10x) — notable because other fast boards had slight regression from L1's Map overhead. L2's duplicate scanning hurts regardless of degree.

6. **Discussed architectural fit.** L1 slots cleanly into the main solver (~2 changes). Orthogonal to symmetry breaking, group ordering, and all other planned improvements. Overhead can be reduced with precomputed neighbor bits and arrays instead of Maps.

7. **Revised the pipeline.** Original L1→L2→L3 linear progression replaced with:
   - L1 (proven, integrate next)
   - L2 proper with grouping (low priority, only for hard degree-3+)
   - L3 pruning via per-neighbor BFS masks (promising, independent of L2, strict prune)
   - L3 heuristic: partition ordering (research territory)
