# 1.3 Path Mask Redundancy — Experiment Plan

## Setup

One script: `research-spike-1/experiments/1.3-path-mask-redundancy.ts`

Run with `npx tsx`. Imports `genPathsDP` from custom-algo-1 and board utilities from test-boards. Uses the same `fromBoardState` / `Board.toIndex` conversion that the solver and tests use.

Runs against all 27 boards in `ALL_BOARDS`. Uses `maxLen = 13` (matching the solver's `maxBurst + 1`).

## Analysis 1: Mask redundancy per board per length

For each board, for each PathEntry length 1–12:
- Total path count
- Distinct mask count (Set of bigint string keys)
- Compression ratio = paths / masks
- Class size distribution: buckets of 1, 2–5, 6–20, 21–100, 100+

Output as a table per board, plus a cross-board summary showing totals and overall compression.

This is the headline measurement. If open-11x11 at length 12 has 60K paths and 2K masks, that's a 30x ratio — dedup is a slam dunk.

## Analysis 2: Overlap-aware equivalence classes

For each board, for each PathEntry length where paths exist, group by:
- `(mask)` alone — same as analysis 1
- `(mask, tiles[0])` — prefix length 1
- `(mask, tiles[0], tiles[1])` — prefix length 2
- `(mask, tiles[0], tiles[1], tiles[2])` — prefix length 3

Report distinct class counts for each grouping. The inflation from pure-mask to prefix-aware tells us how much overlap handling costs us in dedup savings.

The solver's `maxOverlapPerBurst` caps how deep prefixes matter. We compute prefix classes for k=1,2,3 to cover the practical range.

## Analysis 3: Dominated masks

For each board, for each PathEntry length:
- Count masks where there exists another mask at the same length that is a strict superset (i.e., `A & B === A` and `A !== B`)
- Count how many total paths those dominated masks represent

A dominated mask is never the best choice — some other same-length path covers everything it does and more. These are unconditionally prunable regardless of overlap handling.

**Complexity note**: Naively O(n²) per length in distinct masks. For lengths with thousands of distinct masks, we can optimize: sort masks by popcount, only compare masks with lower popcount against those with higher. Still quadratic worst-case but much smaller in practice since dominated masks must have strictly fewer bits set.

Then overlap analysis and dominated mask summary as separate tables.

## What we're not doing

- No solver changes
- No performance benchmarking (that's 1.2)
- No clustering or similarity analysis (that's 4.2) — though if the distribution shows most classes are size 1–2, we'd note that clustering matters more than dedup
- No dedup implementation (that's 4.1)
