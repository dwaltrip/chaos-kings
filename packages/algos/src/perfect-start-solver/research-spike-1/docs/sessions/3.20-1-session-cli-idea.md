# Idea: Session launcher CLI

Interactive CLI script that helps standardize how research sessions start. Inspired by `scripts/start-agent-session.ts` (the session launcher from the ws-refactor epic).

## Core idea

A script that gathers some context interactively (which thread? what kind of work? what's the goal?), assembles a prompt with the right pointers and expectations, and launches `claude`.

The prompt templates would encode our workflow conventions so each session starts consistently without having to remember what to read or how to wrap up.

## Things to figure out

- What are the right session "modes" or types? Some rough ideas: experiment-focused, brainstorm/discussion, review/critique. But this needs more thought.
- How much structure should the prompt templates have? Too rigid and it fights the natural flow. Too loose and it doesn't add value over just typing a prompt.
- Should it read STATUS.md and present active threads for selection, or is that overkill?
- Where does the structured thread/task data live? STATUS.md is markdown — would we want something more structured (JSON/YAML) alongside it, or parse STATUS?
- How does this interact with the docs workflow (LOG, sessions/, findings/)? Should the template tell Claude what outputs to produce, or leave that to the workflow README?

## Prior art

`scripts/start-agent-session.ts` — interactive epic selector, multi-line goal input, assembles prompt, launches `claude` or copies to clipboard. Worth re-reading when we design this.
