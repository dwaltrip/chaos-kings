## Session flow reflection

What worked:
- Reading the three docs in order (README → STATUS → findings) gave clean orientation.
- The architecture exploration as a reusable session note was valuable — paid off immediately during experiment design.
- Opus review of the sketch caught real issues (export gap, ordering change) before implementation.
- Starting with one board (corner-9x9) for a quick sanity check before running all 28 was a good rhythm.

What was friction:
- STATUS was updated before the LOG. Next time, write the LOG first — it's the raw record, and STATUS derives from it.

- Saving experiment output should be the default from the start, not an afterthought.

Suggestions for next session prompt:
