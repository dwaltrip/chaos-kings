# Solver Profiling Overview - Post Bugfix

## Background

Post-fix baseline after session 3.22-5, which fixed a bug in `entryIsFeasibleAggregate` — the `blankTilesWithinDist` heuristic massively underestimated available tiles beyond BFS distance 4, falsely pruning valid entries on open boards. See `sessions/3.22-5-LOG.md` for details.

**pocket-2-11x11** is the only board whose capture count changed (23 → 24). All other boards unchanged.

**On the numbers:**
- The all-boards summary is a single run with no profiling enabled — these are the real performance numbers.
- The deep phase analysis runs with per-call profiling (`{ profile: true }`), which adds significant overhead on high-search-call boards. Compare corner-7x7: 849ms without profiling vs 3.1s with. **Use the counts, percentages, and ratios from the deep profiling, not the absolute times.** The all-boards summary is the perf baseline.
- Pre-fix numbers are in `experiments/output/3.22-3-deep-phase-analysis.txt` and `tmp/3.22-5-solver-output-pre-fix.txt` for comparison.
