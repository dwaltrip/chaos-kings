# Session 3.23-5 — Burst-Aware Dead Tips and Depth Analysis

Extends the prefix set work from 3.23-4 with two new analyses: burst-length-aware dead-tip filtering, and full-depth vs min-depth prefix enumeration. Ends with an assessment of how prefix structure relates to solver design.

## Burst-aware dead-tip filtering

The 3.23-4 dead-tip analysis assumed every burst needs suffix room (free>0 at the tip). But short bursts (pathLen ≤ prefix depth D) fit entirely within the prefix — their tips don't need free neighbors. Burst-aware filtering only checks tips for bursts where `captures[i] + overlaps[i] > D`.

This requires pairing prefix sets with timing entries (which provide per-burst capture counts), not just overlap patterns. We enumerate prefix sets once per overlap pattern, precompute per-tip dead/alive, then cross with all (overlaps, captures) variants from the timing table.

### Results (D=4, N=5, selected boards)

| Board | Naive dead % | Burst-aware dead % | Alive (naive) | Alive (burst-aware) | Ratio |
|---|---|---|---|---|---|
| corner-13x13 | 81.3% | 72.1% | 50,388 | 75,176 | 1.49x |
| pocket-11x11 | 85.8% | 76.3% | 33,178 | 55,318 | 1.67x |
| tight-edge-chokes | 92.2% | 84.4% | 13,358 | 26,525 | 1.99x |
| semi-open-pocket | 46.2% | 34.3% | 317,196 | 386,859 | 1.22x |
| scattered-pockets | 100.0% | 99.7% | 0 | 24 | ∞ (tiny) |
| tight-corner-1 | 100.0% | 98.8% | 0 | 180 | ∞ (tiny) |

Totals are (prefix set × timing signature) pairs, not raw prefix sets — same geometric set counted once per capture distribution.

**Takeaway:** Burst awareness rescues sets that naive filtering would prematurely discard. On medium boards, 1.5-2x more alive pairs. Constrained boards remain almost entirely dead — the geometry is too tight even for long bursts. The dead-tip filter is the pruning power; burst awareness is the correctness guard on top.

## Min-depth vs full-depth prefix enumeration

The enumeration uses variable prefix depth per burst: `depth = max(overlap + 1, 1)`. For overlap=0 bursts, this gives depth=1 (just which general neighbor). Full-depth forces `depth = maxPrefixDepth` for all bursts.

### Why this matters

Burst 0 (always overlap=0) gets a 1-tile prefix at min-depth. Its suffix is `pathLen - 1 = 11` tiles — nearly a full path. The prefix barely constrains the longest burst's direction. At full-depth (D=4), burst 0's suffix drops to 8 tiles, with meaningful directional commitment.

### Results (D=4, N=5, prefix sets per overlap pattern — no timing multiplication)

| Board | Min-depth sets | Full-depth sets | Ratio |
|---|---|---|---|
| corner-13x13 | 1,414 | 123,176 | 87x |
| pocket-11x11 | 1,211 | 4,922 | 4x |
| scattered-pockets | 30 | **0** | gone |
| tight-corner-1 | 76 | **0** | gone |
| tight-corner-2 | 130 | 760 | 6x |
| tight-edge-chokes | 861 | 5,106 | 6x |
| semi-open-pocket | 2,731 | 941,348 | 345x |
| fairly-open | 19,174 | 2,450,390 (capped) | 128x+ |

Three distinct behaviors:
1. **Constrained boards drop to zero.** Can't fit N non-overlapping D=4 paths near the general.
2. **Moderate boards grow modestly** (4-6x). The extra depth adds real constraint without exploding.
3. **Open boards explode** (87-345x). Burst 0 at D=4 has ~24-60 choices with nothing filtering them (coveredMask=0 for first burst).

Full data in `experiments/output/3.23-5-prefix-set-enumeration-{original,FD}.txt` and `experiments/output/3.23-5-burst-aware-dead-tips-full-depth.txt`.

## The depth dilemma

The theory (PREFIX-STRUCTURE-THEORY.md) assumed D=3-4 prefixes for all bursts:

| Burst | Length | Prefix | Suffix |
|-------|--------|--------|--------|
| B1    | 12     | 3-4    | 8-9    |
| B2    | 7      | 3-4    | 3-4    |
| B3    | 3      | 3      | 0      |
| B4    | 2      | 2      | 0      |

But the actual enumeration uses min-depth, giving B1 (the most important burst) a depth-1 prefix. This creates a tension:

- **Min-depth**: manageable set counts, but burst 0 barely constrained (suffix = 11 tiles ≈ full path). Essentially L1 for burst 0.
- **Full-depth**: every burst has directional commitment, but set counts explode on open boards and constrained boards drop to zero.

Neither extreme is right. The theory's value — resolving cross-burst conflicts cheaply in the prefix domain — requires deep enough prefixes to actually capture directional commitment. But uniform full-depth is too aggressive.

## Assessment: prefix structure and solver design

### What's validated
- Prefix pools are small (24 at D=4 on corner boards)
- Fan-out narrowing is steep (~24x at D=4)
- Most prefix sets are self-defeating (dead tips kill 78-100% on constrained boards)
- Burst awareness prevents over-pruning of viable sets

### What's NOT validated
- **Suffix independence** — the theory's big claim (suffixes don't interact once prefixes are fixed) has never been tested
- Whether prefix sets actually contain the solver's solution
- Per-burst candidate counts within a prefix set

### Possible solver architectures

**A) Enumerate-and-extend:** Enumerate prefix sets → extend each burst's suffix independently. The theory's proposal. Needs manageable set counts AND short suffixes AND suffix independence. The depth dilemma hurts: min-depth gives manageable counts but long B1 suffix; full-depth gives short suffixes but unmanageable counts (or zero).

**B) Prefix-partitioned search (="L4"):** The current solver, but partition candidates by D=4 prefix instead of depth-1 neighbor. Each partition has ~1,500 paths instead of ~18,000 (24x reduction from fan-out data). Incremental enhancement — doesn't require suffix independence or prefix set enumeration.

**C) Hierarchical:** Fix burst 0's D=4 prefix (24 choices). For each, enumerate compatible prefixes for remaining bursts (small due to overlap + deeper coverage from burst 0). Extend burst 0's 8-tile suffix. Later bursts are mostly within-prefix. Combines enumeration for the constrained part with search for the unconstrained part.

### What's missing

All three architectures depend on understanding the suffix search space, which we haven't measured. Candidate scoping (analysis direction #4) would answer:
- How many suffix candidates exist per burst within a prefix set?
- Do suffixes actually interact or are they independent?
- What's the total search space per prefix set?

Without this data, we're choosing architectures based on prefix-side analysis alone.
