## What was done

Benchmarked core bitmask operations (overlap check, popcount-of-AND, union, AND-NOT, and a hot-path combo) with BigInt vs Uint32Array at 6 mask sizes: 49 bits (7x7) through 2500 bits (50x50).

Experiment script: `experiments/3.22-2-bigint-vs-uint32array.ts`

## Preliminary observations

**No cliff.** Both BigInt and U32 scale linearly with mask size. BigInt doesn't suddenly degrade at any board size. This answers the primary question — there's no board-size wall to worry about.

**U32 wins on popcount (2.5-3.3x at target sizes).** BigInt's `m &= m-1` loop is O(set bits), vs U32's parallel bit tricks which are O(words). This is the largest single-operation gap.

**U32 wins on overlap check (1.8-1.9x at target sizes).** U32 can early-exit on the first overlapping word. BigInt computes the full AND then compares to zero.

**BigInt wins on union (0.7-0.84x at target sizes).** V8's internal BigInt representation apparently handles OR efficiently — possibly avoiding per-word loop overhead. The gap grows with size, reaching 0.40x at 2500 bits.

**Hot-path (overlap + branch + union): U32 is 1.7-1.8x at 625-900b.** This is the most relevant number — it approximates the solver's inner loop pattern. Meaningful but not transformative.

**U32 advantage narrows at large sizes.** U32's explicit word-by-word loops scale linearly with word count. At 2500 bits (79 words), the loop overhead catches up and U32's advantage shrinks to 1.1-1.2x on overlap/hot-path, while union/and-not flip to BigInt winning.

## Methodology caveats

**Microbenchmark, not end-to-end.** Per-operation timing in a tight loop doesn't capture cache interactions, branch prediction patterns, or recursion overhead from the real solver. Real end-to-end impact could differ from these per-op numbers.

**Random masks, not spatially realistic.** Test masks have bits randomly distributed across all words. Real path masks are spatially contiguous (self-avoiding walks), so set bits cluster in a few words. This mainly affects the overlap early-exit behavior — U32's advantage there could be different with realistic masks. Popcount and union/and-not are unaffected by bit distribution.

**GC pressure unmeasured.** Every BigInt binary op allocates a new BigInt object. Uint32Array writes to a pre-allocated buffer. Over millions of inner-loop iterations, BigInt's GC pressure could degrade performance beyond what this benchmark shows. This would make BigInt look *better* here than in practice.

**Adequate but not high-confidence numbers.** 500K iterations, 10K warmup. Individual benchmarks run ~15ms — shorter than ideal for smoothing noise. Relative ordering is reliable; exact magnitudes (1.8x, 3.3x) are ballpark.
