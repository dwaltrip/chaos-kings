# Session 3.23-4 — Prefix Set Initial Exploration

This session takes the first direct measurement of **prefix set** counts. The central question: for a given board and overlap pattern, how many mutually compatible ways can we assign directional prefixes to a set of bursts?

This builds on session 3.23-3, which validated the prefix structure theory's predictions about individual prefixes (small pools, steep fan-out narrowing, tips that open up). Now we're looking at *sets* of prefixes — how they interact with each other when assigned to multiple bursts simultaneously.

See `PREFIX-STRUCTURE-THEORY.md` for the full theory. See `sessions/3.23-3-prefix-enumeration-results.md` for prior individual prefix data.

## Key concepts

- **Prefix (at depth D):** A non-backtracking path of D tiles from the general (general excluded). It represents the "directional commitment" of a burst — the first few moves that determine where the burst goes. For example, at D=4, a prefix is a 4-tile path from the general.

- **Prefix pool:** All possible prefixes at a given depth D on a given board. The pool is small by construction — bounded by the general's degree and the local branching. Typical sizes: 2-24 at D=4 on degree-2 boards, up to 60-96 on degree-4 boards (depending on mountain density near the general).

- **Prefix set:** An ordered tuple of prefixes, one per burst, that satisfies overlap compatibility constraints. The set is built sequentially: burst 1's prefix is chosen freely, burst 2's prefix is checked against burst 1's coverage, burst 3 against the combined coverage of bursts 1+2, etc. The overlap pattern (e.g., `[0, 3, 2, 1, 0]`) determines what "compatible" means for each burst — zero-overlap bursts must avoid prior tiles, overlap-K bursts must retrace K tiles of prior coverage before diverging.

- **Overlap pattern:** An array of per-burst overlap amounts (e.g., `[0, 1, 1, 0]`). First burst is always 0. These are derived from timing entries (board-independent) and determine the compatibility constraints between prefixes in a set.

- **Tip:** The last tile of a prefix. The point where the prefix ends and the suffix begins.

- **Prefix/suffix boundary:** At depth D, the prefix captures the directional commitment near the general. Beyond the tip, the **suffix** is the remaining path that the burst must follow to reach its full length. A prefix with free≥2 at its tip has multiple continuation options; free=0 means the tip is boxed in with no room to extend.

- **Dead tip:** A tip with free=0 (no walkable neighbors outside the prefix set's combined tile coverage). A prefix set with a dead tip has at least one burst that can't extend beyond its prefix — unless that burst is short enough to fit entirely within the prefix (see "Important complication" below).

## Setup

8 boards tested (3 simple slow, 3 realistic slow, 2 realistic fast for contrast). Ran at D=3 and D=4. Overlap patterns derived from timing table (cap 20-24, deduplicated across capture targets).

Full data in `experiments/output/3.23-4-prefix-set-enum-D{3,4}.json`.

## Key findings

1. **Per-pattern prefix set counts are moderate on hard boards.** On corner-13x13 at N=5, D=4: median 24 sets per overlap pattern, max 148. On pocket-11x11: median 22, max 126. The theory conjectured "tens to low hundreds" of viable prefix sets per board. The per-pattern counts are consistent with this — and since only a subset of overlap patterns are viable on any given board, the per-board total for *viable* sets may well land in that range. We've just started investigating viability (see dead-tip analysis below), so this remains an open question.

2. **Most prefix sets are geometrically self-defeating.** When checking tip freedom against the full set's tile coverage (not just the individual prefix's own tiles), 78-100% of sets on constrained boards have at least one dead tip at N=5. The count of sets where every burst has room to extend is much smaller. For example, across all overlap patterns on corner-13x13, total sets drop from 1,414 to 306.

3. **Dead-tip filtering is strongest where it's needed.** Constrained boards (scattered-pockets: 100%, tight-corner-1: 100%, tight-corner-2: 97%) are almost entirely dead-tip sets at N=5. Open boards that already solve fast (fairly-open: 25%) have the most surviving sets. The filter provides the most leverage on exactly the boards where the solver struggles.

4. **Pool size is the dominant driver of total set counts.** scattered-pockets (pool=2) → 50 total sets at N=6. fairly-open (pool=60) → 271K. The relationship is super-linear — 30x more prefixes leads to roughly 5000x more sets.

5. **Timing only filters overlap patterns at high captures.** At cap≤20, every combinatorial overlap pattern (4^(N-1)) appears in the timing table — timing is loose enough to allow anything. At cap=24, heavy filtering kicks in: only 37 of 256 patterns survive at N=5, 201 of 1024 at N=6. This means the tightest solver scenarios (high captures, where the solver spends the most time) also have the fewest overlap patterns to consider.

6. **D=3 vs D=4 is similar on constrained boards** — pools are nearly the same size because geometry constrains branching regardless of depth. Open boards see more difference since their wider geometry allows more branching at deeper depths. (D=3 data in JSON output; similar patterns, not tabled here.)

## Important complication: dead tips aren't always bad

A burst with 2 captures at D=4 is fully resolved within the prefix — its tip doesn't need free neighbors because there's no suffix to extend. The dead-tip filter is only meaningful for bursts whose path extends beyond D. This means dead-tip analysis ultimately needs burst-length awareness, tying it back to timing entries. For now the analysis uses a worst-case assumption (all bursts need suffix room).

### Dead-tip analysis (D=4)

A prefix set has a "dead tip" if any prefix's tip has zero free neighbors when checked against the combined tile coverage of all prefixes in the set (plus the general). This is a stronger check than looking at each prefix in isolation — a tip might have free=2 on its own, but both neighbors could be claimed by other prefixes in the same set.
